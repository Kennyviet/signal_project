# Cardio Data Simulator
The Cardio Data Simulator is a Java-based application designed to simulate real-time cardiovascular data for multiple patients. This tool is particularly useful for educational purposes, enabling students to interact with real-time data streams of ECG, blood pressure, blood saturation, and other cardiovascular signals.

## Features
- Simulate real-time ECG, blood pressure, blood saturation, and blood levels data.
- Supports multiple output strategies:
  - Console output for direct observation.
  - File output for data persistence.
  - WebSocket and TCP output for networked data streaming.
- Configurable patient count and data generation rate.
- Randomized patient ID assignment for simulated data diversity.

## Getting Started

### Prerequisites
- Java JDK 11 or newer.
- Maven for managing dependencies and compiling the application.

### Installation
1. Clone the repository:
```sh
   git clone https://github.com/tpepels/signal_project.git
```
2. Navigate to the project directory:
```sh
   cd signal_project
```
3. Compile and package the application using Maven:
```sh
   mvn clean package
```
   This step compiles the source code and packages the application into an executable JAR file located in the `target/` directory.

### Running the Simulator
After packaging, you can run the simulator directly from the executable JAR:
```sh
java -jar target/cardio_generator-1.0-SNAPSHOT.jar
```
To run with specific options (e.g., to set the patient count and choose an output strategy):
```sh
java -jar target/cardio_generator-1.0-SNAPSHOT.jar --patient-count 100 --output file:./output
```

### Supported Output Options
- `console`: Directly prints the simulated data to the console.
- `file:<directory>`: Saves the simulated data to files within the specified directory.
- `websocket:<port>`: Streams the simulated data to WebSocket clients connected to the specified port.
- `tcp:<port>`: Streams the simulated data to TCP clients connected to the specified port.

## Week 4 — Design Patterns

### What Was Implemented
Four design patterns were applied to improve the flexibility and maintainability of the alert system.

#### 1. Factory Method Pattern
- **AlertFactory.java** — abstract base factory with `createAlert()` method.
- **BloodPressureAlertFactory.java** — creates blood pressure alerts.
- **BloodOxygenAlertFactory.java** — creates blood oxygen alerts.
- **ECGAlertFactory.java** — creates ECG alerts.

#### 2. Strategy Pattern
- **AlertStrategy.java** — interface defining `checkAlert()`.
- **BloodPressureStrategy.java** — checks BP thresholds and trends.
- **HeartRateStrategy.java** — monitors abnormal ECG peaks via sliding window.
- **OxygenSaturationStrategy.java** — checks for low saturation and rapid drops.

#### 3. Decorator Pattern
- **AlertDecorator.java** — abstract base decorator wrapping an Alert.
- **RepeatedAlertDecorator.java** — adds repeat interval information to alerts.
- **PriorityAlertDecorator.java** — adds priority tagging (e.g. HIGH, URGENT).

#### 4. Singleton Pattern
- **DataStorage.java** — updated with `getInstance()` to ensure a single instance.
- **HealthDataSimulator.java** — updated with `getInstance()` to ensure a single instance.

### Unit Tests

## Week 5 — Real-Time WebSocket Data Processing

### What Was Implemented
The system was transitioned from file-based batch processing to real-time
data processing using WebSocket APIs.

#### 1. DataReader Interface Update
- Added a default `disconnect()` method to support WebSocket disconnection
  without breaking existing file-based implementations.

#### 2. WebSocketClientImpl.java
- Connects to the signal generator's WebSocket server.
- Receives real-time patient data messages continuously.
- Parses each message in the format `patientId,timestamp,recordType,value`.
- Stores parsed data directly into `DataStorage`.
- Handles errors gracefully — malformed or corrupted messages are logged
  and skipped without crashing.
- Supports clean disconnection via `disconnect()`.

### Error Handling
- Wrong number of fields in a message — logged and skipped.
- Non-numeric values in a message — caught with `NumberFormatException`, logged and skipped.
- Connection interruption — caught with `InterruptedException`, wrapped in `IOException`.
- Null DataStorage — detected and logged before attempting to store.

### Unit Tests
- **WebSocketClientTest.java** — covers valid message parsing, malformedmessages, corrupted numbers, null storage, multiple messages, different atients, empty messages, and clean disconnection.
